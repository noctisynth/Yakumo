# RFC 工作流

文档编号：RFC-0000。状态：Active。更新：2026-10-14。

RFC 记录尚未确认或会改变架构边界的提案。已确定需求写入 Active Spec，观察写入 FACT，
验证写入 EVIDENCE，实施差距写入 TASK；它们不能互相代替。

| 状态 | 含义 |
|---|---|
| Draft | 提案仍有待决项，不作为已冻结设计，不生成对应实现任务 |
| Accepted | 关键范围、边界和验收条件已确认，记录接受依据及日期，再同步规范与清单 |
| Rejected | 不采用，保留原因 |
| Superseded | 被后续决策替代，用文档编号关联 |

提案使用四位递增编号，包含问题、目标、非目标、候选方案、影响、验收条件和待决项。
不因创建文档就自动接受提案。用户已经指定的技术栈不需要再通过 RFC 重新审批。
实现中的普通可逆细节可在已有授权内决定；新增关键范围则遵循用户指令和既有设计边界。
接受后按 DESIGN-001 → 相关 Spec → TASK → 实现的顺序同步。
