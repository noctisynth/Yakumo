# 后续实现选项

文档编号：RFC-0001。状态：Draft。更新：2026-10-14。
相关：SPEC-001、FACT-002、FACT-004。本文不改变用户已经确定的技术栈或生成上报目标。

## 问题与目标

协议已具备单校样本的有效提交证据，但应用尚不存在。需要确定跨平台交付、凭据保护、
生成体验、状态恢复和协议兼容边界，避免把历史测试脚本直接作为产品架构。

## 待决项与候选方向

| 项目 | 候选方向 | 尚需收敛的条件 |
|---|---|---|
| 平台矩阵 | 桌面先行，或桌面加移动同步 | 目标操作系统、发行方式、各平台验证环境 |
| 工程组织 | 单应用加内部 Rust 模块，或独立协议与领域 crate | 可测试性、复用需求、拆分收益 |
| 前端构建 | 与 Tauri 兼容的 React 构建工具和包管理器 | 版本、开发环境、锁文件及 CI 一致性 |
| 凭据存储 | 系统凭据库，或经评估的跨平台加密存储 | 密钥生命周期、退出清理、平台支持与恢复 |
| 运动草稿及提交尝试 | 事务数据库，或小规模版本化文件 | 崩溃恢复、并发提交、迁移和私密数据保护 |
| 生成器 | 参数化几何路线，或地图交互路线 | 坐标体系、围栏和必经点、道路语义、可复现性 |
| 状态规则 | 独立领域模型加学校适配 | 异常、人脸、步数、动态时间上限的证据覆盖 |
| 公共兼容材料 | 按样本版本配置的协议元数据 | 登录 Basic 常量、版本字段、signatureMD5 和设备标识策略 |
| HTTP 兼容 | 明确列出的学校端点及传输策略 | 可用 HTTPS、重定向控制、用户可见传输说明 |
| Tauri 命令合同 | 按用例划分的类型化命令 | 输入校验、错误类型、取消、进度及敏感边界 |

建议以离线可复现的协议与生成领域逻辑为先，随后接入身份和只读查询，再做提交及结果核对。
这是推进建议，不是具体库、平台或存储选型已被接受的声明。

## 非目标

不在本提案中新增广告、第三方追踪、自动后台批量上报或全量原版功能克隆。
不把真实传感器采集、Android 前台服务和人脸采集自动提升为当前生成产品的必做范围。
不承诺所有学校、所有运动类型或任意生成样本都有效。

## 接受条件

为选定范围写出目标平台、模块职责、敏感数据边界、提交不确定性处理和验收矩阵。
具体协议疑点需给出已验证支持范围及未支持行为；不能靠填固定状态值绕过建模。
接受后更新 SPEC-001 和 TASK-001；未确认选项继续保留为 Draft。
