# 应用骨架规范

文档编号：SPEC-002。状态：Active。更新：2026-10-14。
依据：用户授权初始化工程；SPEC-001 的技术栈、隐私和命名约束继续生效。

## 本轮选择

- Tauri 2 + Vite + React + TypeScript，Bun 管理前端依赖和文本锁文件。
- Rust 工具链文件选择 stable，并要求 rustfmt 与 Clippy；提交 Cargo 锁文件。
- 首阶段采用单应用及内部模块，不预先拆分协议 crate；版本管理阶段建立单成员 Cargo workspace，见 SPEC-003。
- React Router 使用 HashRouter，适配打包后的静态入口；首页、设置页与未匹配页面构成导航基线。
- Zustand 仅管理界面设置，通过内存状态验证更新；本轮不增加用户数据或会话持久化。
- shadcn/ui 使用本地组件源码及 Tailwind CSS，通过组件配置和统一别名继续生成组件。
- 用户明确要求前端必须使用 Tailwind CSS，尽可能避免原生 CSS；组件和页面全部使用工具类。
- 页面只展示项目准备状态及界面偏好，业务登录、运动生成和服务器提交仍在后续清单。

上述是本轮授权内的工程选型。平台发布矩阵、凭据存储、运动数据存储及地图等未定选项继续留在 RFC-0001。

## 职责与配置

前端按 models、components、pages、stores、hooks、services、lib、routes、styles 组织，
应用源文件使用 kebab-case。Tauri 保留的 Rust 文件遵循框架与 Rust 命名约定。
models 描述界面设置与原生信息；stores 管理设置；hooks 将设置应用到界面；services 封装原生调用；
pages 组合组件；routes 负责导航；lib 保留纯工具；styles 定义全局主题。

初始化阶段原生侧只提供读取应用名称和版本的无副作用命令；后续账号命令及敏感边界由 SPEC-004 扩展。
浏览器预览须能识别非 Tauri 环境并正常展示。调用失败通过可读状态反馈，不使用虚构的原生成功结果。
不安装网络、shell、文件、自动更新或外部链接插件；窗口权限按当前功能最小化配置。
采用本地字体回退，不依赖远程字体、脚本或运行时资源服务。

Biome 作为前端格式与 lint 入口，配置两空格、JS/TS 与 JSX 单引号，启用文件名检查及 import 整理。
JSON 使用双引号，Tailwind 指令由 CSS parser 配置支持；生成组件也纳入检查。
TypeScript 独立检查应用代码及构建配置；编辑器缩进和换行约定与格式工具一致。
Git 忽略依赖、构建产物和本机环境配置，提交源码、配置及锁文件。

## 验收

- 依赖安装与锁文件一致，前端格式、lint、类型检查和生产构建通过。
- stable Rust 格式、Clippy 与相关测试通过，至少在当前 Windows 环境完成 Tauri 无安装包构建。
- 浏览器验证导航、未匹配路由、设置更新及窄屏布局；原生构建结果不冒充所有平台验证。
- 工程文档同步实际版本、脚本入口、已实现范围和剩余工作，不写入本机目录或来源工作区信息。
- 检查通过后提交；若存在实质环境阻塞，准确记录已通过和未完成的验证。
