# 配置、运行状态与验证结果

文档编号：FACT-004。状态：Verified within stated scope。更新：2026-10-14。
证据：EV-09 至 EV-14。这里描述原版与历史实验，不把测试脚本等同于新产品实现。

## 1. 数据链路

学校入口 → 登录及会话 → 原始 appId → 配置请求与解密 → identify 与时间基准 →
本地运动数据及状态 → 字段序列化 → 加密封包 → 双层表单及签名 → 上传 →
按返回记录标识查询详情 → 有效列表核对 → 汇总核对。

原版真实运行会按配置引入注册、人脸、天气、必经点、围栏、暂停和恢复分支。
历史合成实验省略了服务端开始接口以及真实 Android 定位、计步和后台生命周期。
新产品目标是生成与上报，不能将省略的环节写成“全部原版流程已实现”。

## 2. 学校设置

两份原版 getSetting 响应均成功解密，包含 49 个键；完整类型观察保存在 DATA-001。
当前观察值包括 totalRange=1、minSaveRange=0.1、startQualifiedTime=4、endQualifiedTime=20、
limitSpeed="3.33"、startStride="0.6"、endStride="2.3"、startLimitStepFrequency="80"、
endLimitStepFrequency="300"。这些是特定配置，不得作为跨校默认规则。
minSaveRange 与 totalRange 含义不同；startStepFrequency 与 startLimitStepFrequency 不是同一键。
runType 等本质数值有字符串表达，客户端需按字段解释；不将所有 "0"/"1" 一律解析成布尔。

配置失败曾出现 HTTP 999/code=1 和“请更新最新版App[60004]”；更换公开版本及证书参数后，
另一测试场景返回“今日跑步里程已达标”。前者说明有兼容性检查，后者是业务限制；不是网络故障。
静态样本版本与原版成功抓包版本不同，不应盲目宣称版本越新越能通过。

## 3. identify 与时间

原版优先使用 settings.identify，否则 UUID；它关联缓存、状态和上传。
原版入口在非本地续跑情况下请求 getExerciseStartTime，保存返回 startTime 及 elapsedRealtime
基准。运行开始仅在当前值为 0 时初始化，按基准加单调时钟增量，缺失时回退设备时间。
结束时间也使用基准加增量；sportTime 则按有效秒累计，暂停不增加。

HAR 中上传 identify 与第二次配置和开始请求一致；上传 startTime 比对应服务端 startTime
晚 50,287 毫秒，与基准加增量的静态路径相容，不能据抓包独立确定具体分支。
检查点 time 来自设备时间及默认时区，与上述基准不同。
三个 checkExerciseRecord 请求在上传之前，不是该次上传成功证据；其重复提交协调语义未闭合。

## 4. 人脸状态与本地有效性

isFaceStatus 不是“是否开启人脸识别”：运行状态初始化为 true，异常流程变 false，上传映射为
"1" 或 "0"。开始、结束、中途识别分别由 isStartFace、isEndFace、middleFaces 等控制。
needRegisterFace、livingFace、isMidwayFace、faceOutCanContinue 有独立意义，不能互相替代。
恢复本地运动时，从缓存 isFaceOut 字符串转换布尔；变量名不足以判断语义。

人脸异常流程会比较当前位置和相关暂停或检查位置；反编译常量必须解释为 double 1000.0，
不能把底层位模式整数当距离乘数。状态与检查序号存在持久化路径。
成功抓包未出现 URL 含 face 的请求，只证明该捕获范围未见，不证明此前从未注册或其他通道未调用。

上传 isValid 来自 momentIsValid 整数列，区别于同表另一 isValid 字符串列。
计时、距离、步数变化触发本地检查，达标后按 identify 更新 momentIsValid=1。
它是客户端状态，不是服务端判定。测试脚本最初固定 isFaceStatus="0"、isValid=0，与正常
初始人脸状态及已达标情况不一致；随后修正后取得有效记录。

历史实验按已保存的字节码使用如下时间谓词，保留其不寻常结构以免误写成普通区间检查：

```text
time_ok = NOT(duration < min_minutes * 60 AND
              (max_minutes == -1 OR duration > max_minutes * 60))
eligible = time_ok AND rounded_distance_km >= configured_distance_km
                   AND steps >= required_steps
```

该谓词是实验实现及静态跟踪事实，不是经边界穷尽的服务端规则，不应未经复查直接冻结成产品校验。
历史实验距离向下取至 10 米；超过基础距离时，距离比例按十位小数 HALF_UP，开启步数递增时
步数阈值向上取整，非 -1 的时间上限按比例向上取整。
成功样本本地检查结果为 required_steps=1000、observed_steps=2397、dynamic_end_minutes=41。

## 5. 合成样本与结果分层

实验采用五圈合成圆环和平滑相关扰动，可重复生成；目标 2021 米、899 秒、900 点、2397 步。
逐段球面距离累加误差小于 1 毫米；时间间隔与速度、分钟桶与累计步数、38 键并集、AES 回读和
双层表单编码均通过该次检查。路线没有道路匹配，设备字段为占位值，不代表设备认证完整复现。
进一步离线复核 EV-11/EV-12 的实验实现：坐标扰动使用前值 0.92 的相关项与每步均匀小增量，
扰动后重新累计球面距离、按段重算速度，分钟桶由点级累计步数相减。这是历史合成实验的生成方法，
不代表原版真实定位分布或服务端审核模型，也不把某一组噪声常量当作成功原因。


| 层次 | 第一次实验 | 第二次实验 |
|---|---|---|
| 提交 | HTTP 200/code=0，返回记录标识 | 同样返回成功及记录标识 |
| 详情 | status="0"，人脸对比超出规定范围15 | status="1"，合格15 |
| 有效列表 | 不包含该记录 | 包含该记录 |
| 汇总 | 未变化 | 有效次数加一，距离增加 2.02，sumTime 从 "0.00" 到 "0.25" |

两次实验共同变化多个字段，不证明某一个字段的独立因果作用。两种备注末尾都有 15，其含义
仍未知，不能解释为 15 米或 15 秒。两条记录均被保留，历史工作已停止进一步上传。

## 6. 仍然未知

服务端完整必填、范围、跨字段约束、所有模式与上传类型、identify 去重、响应丢失后的
可靠对账、跨账号与跨校差异、设备环境证明、所有人脸和异常恢复流程仍未穷尽。
单个成功样本不能把这些缺口改写成已完成；这些缺口也不抹去已确认的有效记录证据。
